## Findings in the released code

1. **`count:words_japanese` default generator crashes.** `build_description()` with no arguments raises `TypeError` (it tests `N % 10` on the argument, not the drawn value). The adapter draws N exactly as the released default would (`random.randint(1, 30)`, one call on the same RNG) and passes it in. Wording is unchanged.
2. **`count:words_japanese` wording drops the word "word" for some N.** For every N ending in 1, 2 or 3 the text reads e.g. "Every 21st of your response must be in Japanese." (and "11st", "12nd", "13rd"); about 30% of draws. Kept exactly, per the decision to preserve official wording. N = 1 asks for every word to be Japanese.
3. **NLTK 3.10.4 refuses data directories that are group-writable.** `fetch_source.sh` now runs `chmod -R go-w` on the vendored data.
4. No candidate renders a multi-line instruction, so the ManyIFEval one-rule-per-line layout works unchanged.
