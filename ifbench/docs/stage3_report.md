# Stage 3 report: pairwise compatibility audit and six-rule pilot

Generated by `scripts/stage3_report.py` from `freeze/stage3_summary.json` (built by `scripts/stage3_summary.py`). Every number below comes from that file.

## Method

- All 861 pairs of the 42 candidate types. Each *version* of a pair (one setting of its parameters) gets exactly 24 seeded builder attempts. Versions per pair (Nicky, 2026-11-24): **one** if both rules are fixed; **every parameter combination** if the pair has fewer than 50 (list separators, conjunction, repeat, increment, number and pronoun counts); otherwise **50 parameter draws** from the released default generators (seed 20261124). Pairs by category: 351 fixed, 172 all-combinations, 338 50-draw.
- A witness must pass both official verifiers and both frozen plain-meaning checks.
- A pair is **compatible** if any version gives a witness; the success share is witnesses / versions. For a fixed pair the share is 0 or 1.
- Versions already run in the final pairwise run were replayed from their records (the builder is deterministic); 645 versions were run with the current builder: the combinations the final run never drew, and every version of the 39 `format:thesis` pairs after the thesis fix (full stop inside `</i>` under `words:last_first`, approved 2026-11-24), which only that layout branch can affect (`scripts/stage3_versions.py`). 18488 versions in total.
- Every pair without a witness was investigated: it is either a **proven conflict** (a written argument in `src/mife_ifb/stage3_proofs.py`; the library facts it relies on are tested) or **unsupported by the builder**. Both lists stay in the inventory; neither pair is co-sampled.
- `ratio:overlap` is run against task texts: 222 provisional base tasks (released prompts with the rule text removed), one task per draw. Stage 4 replaces them with the cleaned task list.
- Builder: current witness.py sha256 `f9b3b1f2c1b641b0…` for the thesis pairs; every other pair is replayed from the final run's builder, which differs only in the thesis branch (hashes per pair are checked by `stage3_summary.py`: {'1ae17eb3ee01': 777, 'f9b3b1f2c1b6': 39}). Earlier passes (`full`, `rerun`) were used to find builder gaps and are not reported.
- D1 is empirical: "compatible" means the builder found a witness, and "unsupported" is not a proof of conflict.
